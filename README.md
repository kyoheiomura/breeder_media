# oyamoto（おやもと｜ブリーダーメディア）　※サイト名は仮

サイト名の oyamoto（おやもと）は「親元」。子犬や子猫が生まれ、親のそばで育った場所のこと。「この子の親元は、どんな人のところだろう」を読んで確かめられるように、という意味を込めている。ロゴのしるしは、親の大きな足あとと、その先を歩く子の小さな足あと。名前を変えるときは `data/site.ts` の `NAME`・`NAME_EN`・`KANA` を直す（ロゴ・title・OGP に反映される）。

犬や猫のブリーダーへのインタビューを軸にした「ブリーダーを読んで選べる」メディア。
コンセプトは **育てたのは、どんな人だろう。**（ブリーダーの声を読んでから会いに行く） 親との向き合い方も、子の育て方も、迎える人への話し方も、人によって違うので、星・口コミ・ランキングでは並べない。判断材料は「インタビュー本文」と、見学で会える相手・検査・お迎えの時期・迎えたあとの連絡・動物取扱業の登録などの「会いに行く前に知りたいこと」。

**販売・仲介はしない。** いま募集している子犬・子猫の一覧は載せない。見学の申し込みは、それぞれのブリーダーの窓口へ送る。

トリマーのメディア「tocotoco」（`../trimmer_interview`）と同じ仕組み・同じデザインの型を土台にし、ブリーダー向けに作り替えた姉妹サイト。色の面をミントからピーチに変えている。

- 取材の質問シート: [docs/interview-question-sheet.md](docs/interview-question-sheet.md)
- 原稿テンプレート: [templates/breeder.mdx](templates/breeder.mdx)・[templates/kennel.yaml](templates/kennel.yaml)

## 技術

Next.js（App Router・全ページ静的生成）／TypeScript／Tailwind CSS v4／MDX＋frontmatter（Zod で検証）。

## コマンド

| コマンド | 内容 |
|---|---|
| `npm run dev` | 開発サーバー（http://localhost:3000） |
| `npm run build` | 原稿の検査 → ビルド → title の検査。どれかで失敗したら止まる |
| `npm run lint:content` | 原稿の検査だけ（スキーマ・参照・NG ワード・情報の鮮度・登録の有効期限・お迎えの日齢） |
| `npm run check:titles` | ビルド後の全ページの title に「ブリーダー」が入っているか |
| `npm run typecheck` | 型チェック |
| `FORCE=1 bash scripts/generate-photos.sh` | ダミーの写真を AI（Codex）で作り直す（FORCE なしなら、無い写真だけ作る） |

## ブリーダー・犬舎を追加する

1. `templates/kennel.yaml` を `content/kennel/<slug>.yaml` にコピーして埋める（地域は `data/areas.ts` にある値だけ。無ければ市区町村を足す）。動物取扱業の登録は、本人に事前に書いてもらった内容をそのまま書く
2. `templates/breeder.mdx` を `content/breeder/<slug>.mdx` にコピーして埋める。写真は `public/images/breeder/`（縦 4:5）と `public/images/interview/`
3. `npm run lint:content` で検査 → `draft: false` にして公開
4. ファイル名が `_` で始まるものは読み込まれない（下書き置き場）。`SHOW_DRAFTS=1 npm run dev` で下書きも表示
5. 相談を増やすときは `data/vocab.ts` の `CONCERNS` に足す

| URL | 中身 |
|---|---|
| `/` | トップ（見出しと写真・ブリーダーさんのことば・新着・相談8つ・使い方・迎える前に知っておきたい決まり・エリア） |
| `/breeder/` | 一覧（フリーワード・相談・エリア・心配ごと・特徴で絞り込み。新着順／エリア順） |

| `/kennel/<slug>/` | 犬舎・猫舎の情報（場所・見学できる日・動物取扱業の登録）と、そこのブリーダー |

## デザインの決まり

- トーンは tocotoco と同じ「かわいくて、すっきり」。あたたかい白の地に、黒い文字とピーチの面。差し色は黄色（しるしとマーカー）。押すものは黒
- 主役は親子の犬・猫とブリーダーの写真と、ブリーダー本人の言葉。言葉はふきだし（`.bubble`）で見せる
- 書体は LINE Seed JP ひとつ（見出しとロゴは 800）
- カードと写真は大きめの角丸、ボタンとしるしは丸い端。色の面は、角の丸い大きなブロックで置く
- 小さな線画（足あと・きらきら）はトップの写真のそばにだけ。フッターの親子のイラストは `scripts/generate-illust.sh` で作る
- 読みたくなる入口：トップの「ブリーダーさんの、ことば」（frontmatter の `hook`）、カードの「章の見出し」
- 動き：スクロールして画面に入った要素が、下からぽんっとはずんで現れる（`.reveal`／ふきだしやしるしは `.reveal-pop`、本文の段落は `.reveal-soft`、質問は横から `.reveal-left`、写真は幕が開くように `.reveal-wipe`）。全ページで、見出し・カード・記事の本文がスクロールに合わせて順に現れる。トップの最初の画面は読み込み時に順にはずんで出て、黄色のマーカーが引かれる。ロゴの足あとは親・子の順に出る。動きを減らす設定では全部止まる
- スマートフォン：ヘッダーはロゴ・「さがす」・メニューのボタンだけ（`components/MobileMenu.tsx`）。トップの「ことば」は横にスワイプ。一覧の絞り込みは最初は閉じておく
- 色を変えるときは `app/globals.css` の `--color-peach`（面と線）と `--color-blanket`（うすい面）。ロゴ・アイコン・OGP の色は `components/Logo.tsx`・`app/icon.svg`・`app/opengraph-image.tsx`

## 守ること（コンセプトと法律から）

- 口コミ・星・点数・ランキング・「人気順」「おすすめ順」は作らない。並び順は新着順とエリア順だけ
- 載せるのは、第一種動物取扱業（販売）の登録があり、自分で繁殖した子を対面で引き渡しているブリーダーだけ。登録番号・有効期限・動物取扱責任者をページに出す（有効期限が切れると `lint:content` が止める）
- 会わずに渡す売り方（配送・来店不要など）、生後56日より前の引き渡しは載せない。日本犬の特例（49日）に当たる場合だけ、検査の警告を確かめて通す
- 健康・性格・成長後の大きさの約束、「遺伝する病気が出ない」という書き方は載せない。検査は名前と受けた事実だけ（`data/ng-words.ts` で検査。公開前・有料掲載の開始前に専門家の確認を受ける）
- ショーの成績や血統、送り出した頭数、色の珍しさ・体の小ささで見せる項目は作らない
- いま募集している子犬・子猫の一覧、「残り1頭」のような期限であおる表示は作らない
- 有料掲載でも表示順を変えない。`listing: paid` のブリーダーには「掲載プラン利用」と自動で表示する
- 価格は通常の幅だけ。値下げを強調しない

## 公開前にやること

- サイト名を決める（いまの「oyamoto（おやもと）」は仮）。商標・同名サービスを確認する
- トップの「迎える前に、知っておきたい決まり」と記事の下の注意書きの文面を、動物愛護管理法にくわしい専門家に確認してもらう
- 公開する場所を決める（ほかの姉妹サイトと同じく media.raxus.inc 配下なら `/breeder/` などのパスで配信する設定が必要）
- `data/site.ts` の `isDummyContent` を `false` にする（robots.txt の全面ブロックが外れる）
- `NEXT_PUBLIC_SITE_URL` を本番ドメインに設定する
- ダミーのブリーダー・犬舎（`content/`）と AI 生成の写真を、実際の取材内容と写真に差し替える（カード下の `SampleNote` も消す）
- プライバシーポリシーを確定する
